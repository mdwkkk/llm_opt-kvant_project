# Компрессия входного контекста для оптимизации локального инференса

## 1. Введение

Современные большие языковые модели (LLM) демонстрируют выдающиеся результаты в задачах рассуждения и генерации, однако их локальное развертывание на потребительских устройствах сопряжено с жесткими аппаратными ограничениями. 

Ключевой проблемой при работе с такими моделями становятся длинные входные промпты (например, при использовании Retrieval-Augmented Generation, RAG, или сложных инструкций). Длина контекста напрямую влияет на два критических параметра:
1. **Потребление памяти**: механизм KV-кэша растет линейно с длиной контекста, что быстро приводит к OOM (Out of Memory).
2. **Задержка первого токена (TTFT)**: время обработки промпта (prefill-фаза) масштабируется квадратично от количества входных токенов.

Таким образом, возникает противоречие: для качественного ответа модели нужен богатый контекст, но аппаратные ресурсы локального устройства не позволяют его обработать без потери скорости или полного отказа системы. 

Наш проект предлагает сквозную (end-to-end) оптимизацию, атакующую проблему с двух фронтов: 
*   **Со стороны модели**: методы квантизации (FP16, 8-bit, 4-bit), исследуемые в смежных разделах нашей работы, сокращают объем занимаемой памяти самими весами.
*   **Со стороны данных**: алгоритмическая компрессия промптов сокращает длину входного текста, снижая нагрузку на KV-кэш и ускоряя prefill-фазу.

В данном разделе мы фокусируемся на втором уровне — компрессии входного контекста.

## 2. Выбор метода компрессии

В литературе выделяются два основных подхода к сжатию промптов: *soft* (мягкая) и *hard* (жесткая) компрессия. 

*   *Soft-подходы* (например, Gist-токены или 500xCompressor) заменяют текст на плотные эмбеддинги. Они дают колоссальные коэффициенты сжатия, но требуют дообучения модели и плохо переносятся между разными архитектурами (что критично для локального инференса, где пользователь сам выбирает модель).
*   *Hard-подходы* работают на уровне токенов, удаляя из промпта неинформативные элементы. Они не требуют изменения весов модели, работают "из коробки" и полностью совместимы с любыми LLM.

Для нашего исследования выбран алгоритм **LLMLingua** и его оптимизированная версия **LLMLingua-2**, так как они обеспечивают лучший баланс между степенью сжатия и сохранением качества на задачах рассуждения (reasoning). Данный метод базируется на оценке информационной энтропии и использует легковесные модели-энкодеры для предсказания важности каждого токена.

## 3. Методология применения LLMLingua

Процесс сжатия контекста в нашем эксперименте включает следующие этапы:

1. **Оценка важности токенов**: Исходный промпт подается на вход компактной модели-энкодеру (например, XLM-RoBERTa). Алгоритм вычисляет вероятностные метрики для каждого токена, определяя его вклад в общий смысл.
2. **Отсечение избыточности**: Токены, имеющие низкую информационную значимость (предлоги, союзы, вводные слова, повторы), отбрасываются. При этом сохраняются ключевые сущности, глаголы действия и числа, критически важные для ответа.
3. **Итеративное сжатие**: Алгоритм позволяет задавать целевой коэффициент сжатия (например, 2x, 4x, 6x). Сжатие происходит последовательно, чтобы не разрушить синтаксические связи между оставшимися токенами.

## 4. Метрики оценки и гипотеза исследования

Чтобы доказать эффективность компрессии, мы планируем замерять следующие метрики при фиксированных параметрах квантизации (например, на 4-битной модели):
*   **TTFT (Time to First Token)**: насколько быстрее модель начинает генерировать ответ.
*   **Скорость генерации (Tokens per second)**: влияние на пропускную способность.
*   **Пиковое потребление памяти (VRAM / RAM)**: удается ли избежать OOM при работе с длинными текстами.
*   **Качество ответа**: оценка сохранения смысла с помощью метрик (BERTScore, ROUGE) или LLM-as-a-Judge.

**Гипотеза исследования**: Применение LLMLingua с коэффициентом сжатия 2x–4x позволит сократить время генерации (TTFT) и пиковое потребление памяти (KV-кэш) на устройствах с ограниченным объемом VRAM, при этом сохранив семантическое качество ответа на уровне, достаточном для практических задач.
